# 观星 AI 分析

已将静态网站迁移到 Sites 的 Vinext / Cloudflare Workers 运行时，保留同一个 Site、URL、访问范围及完整命盘。年度和月度通过 `/api/ai-reading` 真实调用阿里云百炼 Qwen3.7 Plus。不是模拟请求，也不使用规则文案冒充 AI 输出。

## 工作流程

1. 浏览器按真太阳时、夏令时和晚子时选项生成排盘日期及时辰。
2. 新提交的出生资料自动启动今年、明年详批；表单按钮附近告知数据流。旧记录和示例不自动启动。请求只含规范化的年、月、日、时辰、性别和期间，不发送姓名或城市。
3. 服务端验证输入并重新排盘；仅向千问发送推导出的十二宫星曜、四化、年龄、大限和目标期间的证据，不发送原始生日。
4. 千问生成五领域综合分析和月内农历分段解释。服务端校验 JSON、领域完整性与引用依据 ID，回填真实依据。
5. 显示模型及时间，按命盘和期间在 localStorage 缓存（最多 24 份，存储不可用时回退会话缓存）。支持单年、单月、整组 12 个月顺序生成、停止、失败后继续和导出。

未生成的月份明确保留待生成入口，规则索引与 AI 内容分别标注。年度按农历年，月度按公历月；出生前无报告。健康只作生活节奏参考，财运不作证券投资或收益预测。

## 配置

生产密钥 `DASHSCOPE_API_KEY` 通过 Sites runtime secret 配置。不要放在 `NEXT_PUBLIC_*`、源码、hosting.json 或客户端代码。当前 Site 保持 owner-private，付费 API 受 Sites 访问边界保护；如果未来开放公共访问，应先增加每用户限额与账户权限。

本地调用核心集成测试可从 shell 的同名环境变量读取密钥。密钥不要提交。`npm run dev` 使用 Vinext，`npm run build` 生成 Worker；生产使用 Sites build helper。平台运行于 Cloudflare，普通 Next/Vercel 部署需要适配 env 读取。

- `npm run typecheck`
- `npm test`
- `npm run test:ai`
- `AI_LIVE_TEST=1 npm run test:ai`：真实模型测试，会消耗少量 API 额度。

API：[千问兼容接口官方文档](https://help.aliyun.com/zh/model-studio/qwen-api-via-openai-chat-completions/)。模型固定 `qwen3.7-plus`，JSON 输出，180 秒超时（每个生成部分至多进行一次定点措辞修订），服务端固定 URL，密钥不返回前端。此版本未接入对话追问、个人经历数据或原始大型数据集 RAG。

## 100 分评分与具体情景

年运、月运都有综合分和五领域分。评分在 `lib/guanxing/scores.ts` 中确定性计算，AI 不决定分数：基础 60 分；主星亮度庙 +8 / 旺 +6 / 得 +4 / 利 +2 / 平、地 0 / 不 −3 / 闲 −2 / 陷 −6，多主星平均，借星乘 0.6。四化同宫禄 +16、权 +12、科 +10、忌 −18；对宫化忌 −10。本命权重 0.5、本期 1、流月的流年背景 0.45、大限背景 0.35。四舍五入限制 0–100。

月度领域分按农历分段的实际天数加权；年/月综合分为五领域等权平均。页面显示每项加减分和完整公式。此为本站自定的文化参考指数，未经过现实预测验证，不是成功、获利或患病概率。

AI 接收相同分数和排盘依据，给出直白判断、条件式具体情景、可核实的观察信号及行动建议。未知用户实际经历时不编造其职位、收入、婚姻或健康状态。报告缓存升级为 v3，避免显示缺少评分/情景字段的旧报告。

评分验证：`npm run test:scores`，覆盖分数范围、因子求和、权重、跨农历年公历月天数、总分和 AI/页面一致性。


## 完整个人详批（v3）

年度报告现在包含三篇本命总论（性格/能力、事业求财、家庭感情），上一/本/下一大限对照，五领域年度长篇分析，赚钱机会/留财能力/开销压力，所选公历年全部有效月份的具体解读，以及从所选年份起最多十年的逐年判断。年度主体与完整章节并发请求千问，统一 180 秒取消截止；检测到器官/疾病预测或资产配置指令时，只修订对应字段并再次校验；遗漏或引用不完整时定点补全章节并再次校验；仍有部分失败则明确报错，不冒充完整报告。年度详批输入在 `ai-detail.ts` 中重新计算，引用按本命、所属大限、具体年份和月份分别校验。幼年、大限范围外、出生前月份和 2099 年上界均有单独处理。

月份使用公历月，保留全部农历分段；年度仍按农历年。年/月综合和五领域分数完全由服务端原计算规则回填，模型没有改分权限。财运三个侧面是文字解释，不发明没有规则支持的额外分数。AI 不获取案例文本或案例个人资料；不同人的证据来自各自重新排出的紫微盘。新增章节也使用年龄适配与健康/投资/关系表达边界，不拿八字术语替代紫微依据。

「今年＋明年详批」会顺序生成两份报告（共 24 个月；出生前月份排除）。已完成内容按 v3 缓存，失败或手动停止后可继续。导出包含全部章节、月份、分数与依据。旧 v2 缓存不会冒充新详批。

显式真实模型质量检查：`AI_LIVE_TEST=1 npx tsx scripts/regression/guanxing-ai-live-detail.ts`，使用虚构测试资料，将样例写入 `/tmp/guanxing-detailed-live-2027.json`，需要现有环境中的 `DASHSCOPE_API_KEY`，会产生 API 用量。


## 时辰与自动生成

默认选择时辰，早子时（00:00–00:59）与晚子时（23:00–23:59）分开。BirthDraft.timeMode=branch 时，time 仅为内部时辰代表值，界面明确显示时辰范围和“未填写分钟”；不能把该值用于真太阳时或夏令时校正。精确时分为可选模式；旧数据没有 timeMode 时保留精确时分含义。

新提交记录的 autoAnalyze 标记允许页面自动启动现有真实千问服务。队列在命盘页面持有，切换报告/月份/命盘视图不取消。重复请求去重，已生成报告复用，失败不自动无限重试；暂停在会话内记住，可主动继续。改变命盘或离开页面时取消当前请求，已完成报告保留。详批不是即时完成，生成进度显示真实当前期间。

## 大白话详批（v4）

正文采用口述式解读：先给整体判断，再展开工作、钱、感情、家庭和每月生活场景。长文分成自然段；不要求每个情景都写固定条件句。未知职业、婚恋状态仍通过自然条件说明，不把命理推演写成真实经历。参考文案仅用于校准表达，不导入参考人的个性、财富或健康结论。

`ai-voice.ts` 共用文风同时进入主报告、详细章节及补全。只检查正文，不检查技术依据；遇到星名、四化、机械条件句和英文夹杂，仅让 AI 改写命中的字段，保留依据 ID 和服务端评分。健康仍只写作息安排，不输出症状和疾病预测。首段总论移到报告顶部，网页和 Markdown 导出一致。

缓存改用 `gx-ai-v4` 并只读取 version 4。已同意自动生成的资料再次打开时会生成新版，避免继续看到旧文案；旧缓存不删除。单份请求最多 240 秒，界面提示每份通常 1–4 分钟。生成时可先看命盘。

定向修订仅重试仍不合格的字段，最多三轮，保留合格段落。缺少或引用错误的章节按单段补全，每批最多三个请求，避免长批次遗漏。健康领域的正文只保留日程和休息安排；专门校验按摩、补品、身体修复等表述不会进入这一栏。
